# 워치 셀룰러 단독 동작 검증 — 2026-10-03

판정: 현재 작업 트리의 코드와 서버 API는 아이폰 없이 기존 대화의 메시지를
송수신하도록 구현되어 있다. 실제 워치의 셀룰러 단독 동작은 아직 미검증이다.
앞선 전송 수정은 작업 트리에 있으며 설치된 앱에 반영됐다는 증거는 없다.

## 확인한 근거

| 항목 | 결과 | 검증 범위 |
| --- | --- | --- |
| 독립 실행 | 통과 | 소스 Info.plist의 `WKRunsIndependentlyOfCompanionApp=true` |
| 셀룰러 요청 허용 | 코드 확인 | URLSession의 `allowsCellularAccess=true`, HTTPS 직접 요청 |
| 연결 준비 | 코드 확인 | `waitsForConnectivity=true`, 리소스 제한 40초, 경로 감지에 따른 폴링 차단 제거 |
| 아이폰 통신 중계 | 검사 통과 | WatchConnectivity/WCSession/WebSocket 전송 없음 |
| 독립 인증·송수신·읽음 | 테스트 통과 | 아이폰·기존 워치 세션 종료 후 워치 전용 로그인, 송신, 상대방 조회, long poll 수신, 읽음 갱신 |
| 재시도 중복 방지 | 테스트 통과 | 동일 UUID 요청은 동일 메시지 반환 |
| 워치 직접 푸시 | 서버 테스트 통과 | 푸시 발송 대역 및 로컬 HTTP/2 테스트; 실제 APNs 도착은 검증하지 않음 |
| 네이티브 빌드·서명 | 미검증 | 로컬 Xcode 프로젝트·서명된 IPA·Swift/Xcode 없음 |
| 셀룰러 망·실기기 UI·백그라운드 알림 | 미검증 | 연결된 실기기와 실행 기록 없음 |

실행: `bun test apps/server/src/modules/watch` → 38 passed, 0 failed.
`bun apps/app/scripts/watch-build-checks.cjs`의 소스 독립성 검사와 소스 plist 검사도 통과했다.
이 환경에서 EAS 전용 네이티브 검사 분기는 실행되지 않았다.
통합 테스트의 요청은 서버 앱 내부에서 처리되므로 실제 TLS·통신사망 검증이 아니다.

아이폰 세션을 iCloud Keychain으로 공유하는 경로는 선택적인 로그인 편의 기능이다.
워치 화면에서 직접 로그인할 수 있고, 발급된 워치 세션은 기기 Keychain에 별도로
저장된다. 다만 자동 로그인 경로의 저장 실패는 현재 무시되므로 재실행 후 로그인
유지는 실기기에서 반드시 확인해야 한다. 워치에는 친구 추가·수락 UI가 없어,
메시지 테스트에는 다른 클라이언트에서 이미 만들어 둔 대화가 필요하다.

## 실기기 최종 통과 절차

준비: 수정이 포함된 빌드, 활성화된 셀룰러 요금제, 기존 대화 상대, 워치 알림 권한.
빌드 번호·watchOS 버전·기기·통신사·시험 시각을 기록한다.

1. 페어링된 아이폰의 전원을 완전히 끈다. 워치 **설정에서 Wi-Fi를 끄고**,
   제어 센터의 셀룰러 버튼이 녹색으로 연결됐는지 확인한다. 요금제 활성화만으로는
   셀룰러 연결 증거가 되지 않는다. 첫 시험은 저전력 모드를 끈 상태로 수행한다.
2. 워치 앱을 다시 열어 대화 목록과 최신 메시지를 가져오는지 확인한다.
3. 워치에서 고유한 문구를 보내고 상대방의 웹/별도 기기에서 실제 도착을 확인한다.
   상대방이 답장하면 열린 워치 대화에 도착하는지, 읽음 표시가 갱신되는지 확인한다.
4. 워치 앱을 닫았다가 다시 열어 로그인과 메시지가 유지되는지 확인한다.
   이어 워치에서 로그아웃하고 직접 재로그인해 아이폰 없이도 인증되는지 확인한다.
5. 앱을 백그라운드로 보내고 다른 고유 문구를 수신한다. 워치에 실제 알림이 뜨고
   탭하면 해당 대화가 열리는지 확인한다. 서버 APNs 성공 응답만으로 통과 처리하지 않는다.
6. 잠시 셀룰러를 끈 상태로 전송해 실패 메시지가 남는지 확인하고, 다시 연결한 뒤
   명시적으로 재시도한다. 상대방에게 한 번만 도착해야 한다.

각 항목의 실제 관찰 결과가 기록되기 전에는 “셀룰러 단독 동작 검증 완료”로 표시하지 않는다.
